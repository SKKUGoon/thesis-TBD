# XGBoost·환자 구성 직접 예측 방법론

이 문서는 v1.10의 이전 실행 조건을 보존한다. 현재 주 입력과 수정 실행 결과는 [v1.11 표준 입력 명세](STANDARD_FEATURES.md)를 따른다. 이전 실행 코드는 해당 실행 폴더의 source_snapshot에 보존했다.

## 질문과 비교

같은 약품 그룹에서 (1) 약품별 과거 기록·달력, (2) 전체·성별 환자 수 추가, (3) 진단·입원/외래·연령을 포함하는 환자 구성 추가를 비교한다. 같은 특징 후보·원점·라벨·월별 재적합 규칙의 선형 Ridge도 실행한다. 정규화 없는 고차원 OLS를 비교 대상으로 삼지 않는다. 개발에서 각 모형의 지연 길이를 따로 선택하므로 선택된 두 모형의 최종 비교만으로 순수한 선형/비선형 효과를 확정하지 않는다. 같은 지연 조합의 개발 결과도 보존한다.

XGBoost는 고정된 depth=3, eta=0.05, 120 rounds, hist/CPU, max_bin=64, 4 threads의 작은 탐색 예산으로 실행한다. 나무의 광범위한 최적화가 완료된 것으로 주장하지 않는다. Ridge는 학습자료에서만 MaxAbs 입력 스케일을 적합하고 alpha=1/10을 개발에서 선택한다. 원자료/목표에 평균·0을 대입하지 않으며 스케일링을 원본 정제로 표현하지 않는다.

## 환자 구성과 공란

10개 사용 Parquet의 필요한 7개 열만 65,536행 단위로 읽는다. 전체 사용 행의 공란 비율과 연도별 비율을 정확히 집계하고, 진단의 공란·유효 코드 부재는 구분한다. 환자 자료의 공란 때문에 구성 자체가 불가능하다고 판단하지 않는다.

- 일자 기준은 의약품사용일시다. 사용기록에 등장한 환자를 센다. 병원 전체 내원자나 실제 재원자 명부로 표현하지 않는다.
- 환자 수는 날짜·환자·범주의 고유 개수다. 같은 환자의 여러 사용 행은 환자 수에서 반복 계산하지 않는다. 약품 소모 목표에는 반복 사용 행을 모두 유지한다.
- 주상병·부상병은 코드의 첫 ICD 문자 및 주상병 ICD 3자리 단위로 구성한다. 첫 문자를 정확한 공식 ICD/KCD 임상 장 전체로 표현하지 않는다. 같은 환자·날짜에 여러 진단/범주가 기록되면 각 범주에 포함될 수 있어 범주 합이 총 환자 수와 같지 않을 수 있다.
- 모든 ICD3의 일별 고유 환자 수는 별도로 보존한다. 모형은 초기 2020–2022년의 주상병 환자일 빈도 상위 32개 ICD3, 모든 초기 코드 첫 문자 그룹, 부상병 첫 문자 그룹, 공란/유효하지 않은 코드 범주를 사용한다. 그룹 선정에 소비 패턴을 사용한 것이 아니며 환자 특징의 차원 제어다.
- 성별 M/F/OTHER, 입원/외래/OTHER, 고정 연령대 0–17/18–39/40–64/65–79/80+와 미정의 범주를 사용한다. 결측을 평균 연령·흔한 진단으로 대체하지 않는다.
- 단어집/상위 ICD3는 초기기간에서 동결한다. 새로운 코드 첫 문자 등은 OTHER_UNSEEN에 보존한다. 상위 외 ICD3를 합산하면 고유 환자가 중복될 수 있으므로 그 합계 특징은 제외하고 모든 코드별 집계를 따로 남긴다. 희소 진단도 첫 문자 특징에 포함되며 개별 ICD3를 모두 lagged feature로 넣지는 않는다.
- 해당 날짜에 사용기록이 존재함을 확인한 상태에서 범주 환자 수 0은 추출 자료 안의 관측된 범주 개수다. 실제 약품 소모량 0의 확인과 구분한다. 소모 목표의 기존 미관측 53일은 그대로 남긴다.

현재 일별 환자 구성은 105열이다. 공란과 새 범주를 지워 전체 사례를 버리지 않는다. 동일일 사용량을 설명하는 동일일 환자 수는 입력하지 않는다.

## 예측 설계·시간 계약

각 약품 코드의 과거 **recorded_count** 1~k_y일과 환자 구성 1~k_p일을 입력한다. 코드별 기록 수 0은 기록이 없다는 사실이며 실제 소모 0이 확인됐다는 의미가 아니다. k_y/k_p=7/28을 독립 비교한다. 원점 t에서 t−1까지만 사용한다. 실제 전산 반영 시각은 없어 1일 가용 지연 가정 시나리오로 한정한다. 미래 사용 행의 방문일·입원일·퇴원일을 역추가하지 않는다. 공식 정책 발표 이력을 재구성하지 않았으므로 이번 실행에 정책 변수는 포함하지 않았다.

이번 예측은 **horizon-aware pooled direct regression**이다. 학습 행은 과거 예측 원점과 h=1…14의 조합이며, 모델 입력에 h와 대상일 달력을 추가한다. 각 h의 미래 실제 환자·미래 실제 약품을 입력하지 않는다. 기존 계획의 14개 독립 직접 모형 대신 월별 한 모형이 h를 함께 학습하는 계산 절약 조건으로 명시한다. 공동 VARX 또는 14개 독립 모형이라고 부르지 않는다. 같은 설계를 Ridge에도 적용한다.

초기 2020–2022년 이후 2023년 1–6월에서 개발한다. 차수/지연을 고정한 뒤 2023년 하반기와 2024년을 평가한다. Expanding window이며 월 첫 월요일 원점에서 모수/나무를 처음부터 재적합한다. 같은 달에는 모수를 유지하고 새 과거 feature로 예측한다. 학습 라벨의 대상 날짜가 refit 원점보다 앞선 행만 포함한다. 14일 예측을 위한 아직 관측되지 않은 라벨을 학습하지 않는다. 같은 원점·h의 유효 라벨 범위가 모든 모형에서 같음을 검사한다.

앞 1/7/14일 일별 MAE, 편향, 고정 초기기간 MASE, 누적 수요 MAE, 주간 계절 단순예측 대비 skill을 저장한다. 음의 skill은 악화다. 원점 목표기간과 pooled 학습 행은 서로 겹치므로 독립 표본 수로 주장하지 않는다. 2024년은 이전에 EDA/파일럿을 본 후향적 평가이며 미접촉 확증 holdout이 아니다. 같은 제품 행정 코드 2개 그룹의 결과이지 다른 제네릭 전환이나 실제 물류 개선 검증이 아니다.

## 코드·실행

- [patient_data.py](../../src/methods/xgboost/patient_data.py): 전체 열 공란 감사, 환자 구분 집계·초기 단어집 동결·개인정보 제거.
- [forecasting.py](../../src/methods/xgboost/forecasting.py): 과거 시차, direct horizon 행렬, 월별 XGBoost/Ridge 재적합, 체크포인트·예측·gain 기록.
- [run.py](../../src/methods/xgboost/run.py): 개발 선택, 동결, 순차 점검·평가·출처/코드 해시 보존.
- [설정](../../configs/xgboost_patient_composition.json), [집중 검사](../../tests/test_xgboost_composition.py).

```sh
.venv/bin/python -m src.methods.xgboost.patient_data --original data/processed/cheonan/original --output data/processed/cheonan/analysis/NEW_PATIENT_DATASET_ID
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=4 .venv/bin/python -m src.methods.xgboost.run --config configs/xgboost_patient_composition.json --output runs/cheonan/NEW_UNIQUE_RUN_ID
```

새 환자 데이터셋을 쓸 때 설정의 patient_dataset 경로도 별도로 동결한다. 기존 경로에 덮어쓰지 않는다. 체크포인트는 월별 .ubj 또는 Ridge 계수/스케일 .npz로 보존한다. gain은 나무 분할의 학습 기여이며 인과효과나 별도 검증된 feature 유용성으로 해석하지 않는다. 결과 보고서 생성·검증은 [reporting.py](../../src/methods/xgboost/reporting.py)에 보존한다.

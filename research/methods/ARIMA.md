# ARIMA 실행 방법론과 보존 코드

## 이번 실행의 범위

v1.8 연구계획의 단일 그룹 총량 예측을 먼저 구현했다. 이번 실행은 **무기록을 미관측으로 유지한 탐색 실험**이며, 정식 주 실험·물류 효율 개선 검증은 아니다. 사용자 업무 기준인 사용기록 1행 = 기본 단위 1개를 적용하고 반복 행을 모두 보존한다.

소비 빈도·상관·소비 패턴 없이 2020–2022년 병원 품목명·명시된 단위와 외부 제품 정보로 후보를 구성한다. 제품명/제형과 함량이 일치하는 유일한 제품, ATC 5단계, 성분, 동일 기본 단위를 요구한다. 소비를 읽기 전에 그룹을 저장하고, 2–20개 코드인 적격 후보 중 메타데이터 키 순서로 하나를 선택한다. 이번 후보는 뉴론텍캡슐100mg의 gbpt100/gbpt100b다. 서로 다른 제네릭의 군집을 구현했다는 의미가 아니며 같은 제품의 행정 코드 집계다. 경로의 별도 확인과 과거 외부 메타데이터의 가용시점은 미확인이다.

무기록 날짜를 0·평균으로 대체하지 않는다. 일자별 recorded_count의 0은 추출된 기록이 없다는 집계 사실이고 consumption의 NaN은 실제 0으로 확정하지 않았다는 표시다. 모델은 상태공간 likelihood의 누락 관측 처리를 사용한다. 내부 상태 추정은 원본/목표값 보완과 구분되지만, 무기록이 실제 0이면 이 설정은 적절한 주 실험이 될 수 없다. 추출 완전성 확인 뒤 별도의 새 데이터셋·실험으로 관측 0 해석을 적용한다. 양수 행수도 원본 추출 완전성이 확인되기 전에는 완전한 물리적 총소모로 단정하지 않는다.

## 실행 계약

- 초기 이력: 2020–2022년. 개발: 2023년 1–6월. 순차 점검: 2023년 7–12월. 후향적 평가: 2024년. 기존 EDA를 했으므로 2024년을 미접촉 확증 검증으로 표시하지 않는다.
- 월요일마다 H=14일을 예측하고 해당 평가 구간에 14일 전체가 들어오는 원점만 사용한다. 평가기간이 겹치는 원점은 독립 표본으로 세지 않는다.
- Expanding 이력으로 매월 첫 평가 원점에서 모수를 적합한다. 같은 달의 후속 원점은 모수를 유지하고 당시 과거 이력으로 상태만 갱신한다.
- 정보 가용 지연은 **미확인 1일 가정 시나리오**다. 원점 t에서 t−1까지의 기록만 이용하며 사건일과 실제 전산 반영 시각이 같다고 입증한 것은 아니다.
- 후보 ARIMA(1,0,0), (2,0,0), (1,1,0), (0,1,1). d=0은 상수 포함, d=1은 추세 제외. 최대 200회 최적화. 수렴·유한 모수를 요구하고 실패를 기록한다. 개발의 모든 공통 원점에서 성공한 후보의 앞 14일 일별 MAE로 선택한다. 동률은 차수 합, 실행 시간 순이다.
- 선택한 차수는 순차 점검/2024 평가 전에 저장하고 이후 변경하지 않는다. 비음수 투영 max(0, 예측)을 적용하되 원래 예측도 함께 저장·평가한다.
- 기준선은 당시 이용 가능한 마지막 동일 요일의 관측을 반복하는 주간 계절 단순예측이다. 두 번째 주의 실제값을 참조하지 않는다.
- 앞 1/7/14일의 일별 MAE, 편향, MASE, 누적수요 MAE 및 기준선 대비 skill=1−MAE모델/MAE기준선을 기록한다. MASE 분모는 초기 2020–2022년의 관측 가능한 7일 차이로 고정하고 분모가 0이면 미정의로 표시한다.
- 상품 배분은 과거 7/28일 기록 비율의 보조 기준선이다. 개발에서 창을 선택하고 원점별 과거 기록만 사용한다. 개별 코드의 무기록 실제값은 미정의이므로 배분 MAE는 양수 관측에 조건부이며 전체 상품 배분 성능으로 해석하지 않는다.
- 이번 빠른 경로는 약품 자체의 단변량 ARIMA다. 환자 공변량·국가 전염병 정책 변수·SARIMAX·VAR·XGBoost·TimesFM은 실행하지 않았다. 이 연구의 전체 비교 완료로 표현하지 않는다.

## 코드와 재현

코드는 방법론별 디렉터리에 보존한다.

| 파일 | 역할 |
|---|---|
| [data.py](../../src/methods/arima/data.py) | 보수적 메타데이터 연결·선정, 선택 코드만 사용기록 배치 집계, 관측 마스크·출처 해시 저장 |
| [forecasting.py](../../src/methods/arima/forecasting.py) | 과거 컷오프, 월별 Expanding 적합·상태 갱신, 기준선·평가 |
| [run.py](../../src/methods/arima/run.py) | 개발 선택, 평가 실행, 결과·실패·모수·그림·보고서 저장 |
| [설정](../../configs/arima_quick_native_missing.json) | 실행 전 고정한 기간·차수·가용 지연 가정 |
| [과학적 검사](../../tests/test_arima_methodology.py) | 미래 변경 불변성, 메타데이터 그룹 불변성, 반복 행 보존, 무기록 미대입, 기준선 미래 참조 방지 |
| [의존성](../../requirements.lock) | 실제 설치 버전 |

저장소 루트에서 Python 3.12와 의존성을 준비한 뒤 다음과 같이 실행한다. run-id는 새 이름을 사용하며 기존 실험에 덮어쓰지 않는다.

```sh
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.lock
.venv/bin/python -m pytest -q
.venv/bin/python -m src.methods.arima.run --config configs/arima_quick_native_missing.json --run-id NEW_UNIQUE_RUN_ID
```

데이터셋은 data/processed/cheonan/analysis/<run_id>/, 실험은 runs/cheonan/<run_id>/에 저장한다. 원자료를 수정하지 않고 사용 Parquet의 필요한 두 열만 배치 순회한다. 원자료·모형 결과는 비공개 Git 제외이며 실행 코드는 Git 추적 대상이다. 원본 해시, 그룹 해시, 설정 스냅샷, 코드 해시, 의존성, 월별 모수와 학습 끝일, 예측·실제·기준선, 시간 컷오프 검사와 실패 목록을 보존한다.

[statsmodels ARIMA 공식 인터페이스](https://www.statsmodels.org/stable/generated/statsmodels.tsa.arima.model.ARIMA.html), [상태공간 예측 예제](https://www.statsmodels.org/stable/examples/notebooks/generated/statespace_forecasting.html), [누락 관측 상태공간 예제](https://www.statsmodels.org/v0.11.1/examples/notebooks/generated/statespace_sarimax_internet.html)를 참조했다. 예측 모수와 상태 갱신을 분리하고 입력의 NaN을 남기는 설정을 실제 설치 버전과 합성 검사에서 확인한다. 이 구현 근거는 병원 자료의 업무 의미를 대신 확인해 주지 않는다.

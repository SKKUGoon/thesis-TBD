# 천안의료원 약품 소모량 예측과 보충 정책을 통한 물류 효율화 연구계획서

- 작성일: 2026-10-06 (Asia/Seoul)
- 문서 상태: 연구계획서 v1.4. 약품 수량·정책 계약과 순차 예측 설계를 유지하고 모델별 과거 이력 입력 및 지연 특징 설계를 추가. 독립 검토는 v1.0까지이며 이번 대상 변경은 재검토 전이다.
- 연구 범위: 천안의료원 약품 물류를 주 분석으로 하고 물품 출고는 별도 보조 분석으로 유지한다. 기존 서송·이푸른 연구의 결과·모델 정의를 변경하지 않는 별도 계획이다.
- 실행 상태: 무손실 Parquet 변환, 환자·약품 탐색 및 물품 품질·패턴 분석 완료. 약품 일별 소모수량 집계, 모델 입력 생성, 예측·튜닝·정책 실험은 미실행이다.
- 핵심 원칙: 원자료 보존, 미래정보 배제, 환자 클러스터 제외, 예측 기여도와 인과 영향 구분, 실제 재고와 가정 기반 재고 구분.

## 1. 연구 개요

### 1.1 목적

약품의 일별 소모량을 예측하고 예측값을 보충 의사결정에 연결하여, 정해진 공급 수준에서 재고·발주·긴급조달 부담을 줄일 수 있는지 평가한다. 환자 군집 생성이나 표현학습 자체를 연구 목표로 삼지 않는다. 약품 종류별로 과거 소모량·달력·환자 활동량의 예측 기여도를 비교한다.

사용자 제공 업무 기준인 사용기록 1행 = 해당 약품 기본 단위 1개 소모를 연구 수량 계약으로 채택한다. 날짜·약품별 행 수를 목표값으로 집계하여 소모량 예측을 수행하고, 명시적 가정 아래의 보충 정책 비교에 연결한다. 실제 병원 운영 대비 재고·비용 절감은 실재고·주문·납기·기존 정책을 확보하고 검증한 경우에만 평가한다.

### 1.2 연구 질문 및 가설

| 번호 | 연구 질문 | 검증할 가설 | 반증 또는 제한 조건 |
|---|---|---|---|
| RQ1 | 어떤 모델이 약품별 소모량을 잘 예측하는가? | ARIMA 계열·XGBoost·TimesFM 중 일부가 계절 단순예측보다 오차를 줄인다 | 기준선보다 나쁘면 음의 개선을 그대로 보고 |
| RQ2 | 환자 정보가 추가로 유용한가? | 과거 환자 활동량이 소모 이력·달력 대비 추가 설명력을 가진다 | 개선이 없거나 사용 가능 시점을 확인하지 못하면 채택하지 않음 |
| RQ3 | 예측 개선이 물류 성과로 이어지는가? | 동일한 공급 목표에서 평균 재고 또는 비용이 감소한다 | 예측만 개선되고 물류 성과가 악화될 가능성 포함 |
| RQ4 | 종류별로 유용한 변수가 다른가? | 종류에 따라 변수군 제거 효과와 예측 기여도가 다르다 | 표본 부족·불안정한 중요도는 탐색 결과로 제한 |
| RQ5 | 보충 주기 변경이 추가로 유용한가? | 예측 모델을 고정한 상태에서 주기 또는 재주문점 변경이 개선을 만든다 | 발주비용·납기 미확인 시 시나리오 결론만 허용 |

연구의 주 결론은 RQ3의 공급–재고 관계이며, RQ1·RQ2·RQ4는 개선 또는 실패의 경로를 설명한다. RQ5는 분리된 후속 실험으로 수행한다.

### 3.3 약품 소모수량의 조작적 정의

- **수량 정의:** 사용자 제공 업무 기준에 따라 약품 사용기록 1행을 해당 약품 기본 단위 1개 소모로 정의한다. 이는 이번 연구의 명시적 자료 계약이며 별도 수량 열이 없어도 목표값을 구성할 수 있다.
- **집계식:** `daily_consumption(date, drug_code) = COUNT(source_usage_rows)`; 동일 환자·날짜·약품의 반복 행도 모두 포함한다. 원자료를 집계값으로 덮어쓰지 않는다.
- **단위 연결:** 약품 목록의 코드·단위·규격을 연결하되 하나의 코드에 복수 규격·단위가 있으면 적용 기간과 환산 근거를 확인한다. 사용기록 1단위를 입고 1포장으로 임의 환산하지 않는다.
- **기록 범위:** 약품에 해당하는 코드의 연결률과 미연결 코드 수를 보고한다. 단순히 약품 목록에 없다는 이유로 소비 기록을 누락시키지 않는다. 취소·반납·정정의 표현 방식과 추출 파일 간 중첩은 별도로 점검한다.
- **무기록 날짜:** 1행 1단위 계약은 무기록 날짜의 0 해석까지 확정하지 않는다. 해당 날짜·품목이 완전 추출되고 취급 중이며 사용기록이 없음을 확인한 범위만 소모량 0으로 표시한다.
- **근거 표시:** 사용자 제공 업무 기준으로 채택했다고 기술한다. 기관 공식 확인 또는 법률 근거를 확보한 것으로 서술하지 않는다.

## 4. 사전 자료 확인 및 분석 데이터 계약

### 4.1 병원 또는 자료 담당자에게 확인할 사항

| 질문 | 미확인 시 처리 |
|---|---|
| 출고는 중앙창고→부서 이동인가, 환자 소비인가, 재사용품 반출인가? | 창고 출고 예측으로만 기술. 소모품·재사용품·이동 구분이 안 되는 품목의 효율화 해석 보류 |
| 입고는 구매 입고인가, 부서 반납·세척 후 반환인가? | 보충 사건으로만 기술. 구매 발주라고 부르지 않음 |
| 사용기록의 동일 날짜·환자·약품 반복 행 | 1행 1단위 계약에 따라 모두 계산하며 자동 중복 제거하지 않음. 추출 중복이 객관적으로 확인되면 별도 정정 규칙과 버전으로 관리 |

| 단위·포장 수량과 유효기간별 코드 변경이 있는가? | 임의 환산 금지. 확인된 단위별 분석만 허용 |
| 무기록 날짜는 무거래인가, 추출 누락인가? | 미관측 유지. 연속 시계열이 필요한 모델의 실행 보류 |
| 날짜는 거래일·마감일 중 무엇이며 전산 반영이 언제 완료되는가? | 보수적 지연 가정의 후향적 실험으로 제한 |
| 기준일 실재고·주문일·예정입고·납기·부족 요청·비용 자료가 있는가? | 실제 운영 검증 보류. 사전 고정한 시나리오만 수행 |
| 환자기록은 전체 방문·입원을 포괄하는가? 나이·진단은 어느 시점의 값인가? | 관측된 활동량으로 표시. 시점 불명확한 나이·진단은 주 실험 입력에서 제외 |

### 4.2 데이터 계층

1. **원본 보존층:** 현재 CSV·문자열 Parquet 변경 금지.
2. **분석 거래층:** 사용기록별 원본 파일·행 위치, 사용일, 약품코드, 소모 기본수량 1, 연결된 단위와 수량 계약 버전을 보존. 입고·물품 거래는 별도 원문과 규칙을 보존.
3. **일별 분석층:** 날짜×약품×기본 단위의 소모수량, 입고수량, 관측 여부, 취급 여부, 정보 사용 가능 시점. 물품 출고는 별도 테이블로 유지.
4. **모델 입력층:** 예측원점별 과거 입력, 특징 명세, 전처리 적합 범위, 학습 라벨 끝 시점.

결측치를 평균·미래 값·전체기간 통계로 채우지 않는다. 기록이 없는 날짜를 0으로 표현하는 것은 자료 완전성과 무거래 의미가 확인된 경우에만 허용하고, 그 근거를 기록한다. 과거 이동평균은 결측치 대체가 아니라 별도의 모델 특징이며 원본을 덮어쓰지 않는다.

## 5. 약품 분류와 연구 대상 선정

### 5.1 분류 체계

약품명만으로 약효·임상 중요도를 자동 확정하지 않고 병원 약품분류표를 우선 사용한다. 분류표가 없으면 아래 기준으로 임시 분류 후 담당자 확인을 받는다.

| 분류 축 | 예시 | 용도 |
|---|---|---|
| 제형·투여 경로 | 정제 / 캡슐 / 앰플·바이알 / 기타 / 미확인 | 수량 단위와 약품 종류별 성과를 구분. 제형만으로 재고 단위 확정 금지 |
| 약품 분류 | 병원 약효 분류 또는 근거가 확인된 코드 분류 / 미확인 | 종류별 모델 성과와 변수 기여도 요약. 코드 매핑·적용 기간 확인 후 사용 |
| 소모 패턴 | 빈번 / 간헐 / 변동이 큰 소모 | 학습기간 기반 층화와 모델별 적용 범위 |
| 운영 중요도 | 담당자가 지정한 중요도 | 서비스 목표 구분. 명칭으로 임의 임상 중요도 부여 금지 |

`item_code`, `unit`, `category`, `classification_basis`, `effective_from/to`, `review_status`를 분류표에 저장한다. 미래 시점의 분류·규격으로 과거 품목 정보를 덮어쓰지 않는다. 분류가 모호하면 `미확인`으로 유지한다.

### 5.2 대상 선정 규칙

소규모 비교는 학습기간 2020–2022년에서 결정한 20–30품목을 목표로 한다. 먼저 업무 의미·단위·관측 범위를 통과한 품목을 선정하고, 소모 빈도·변동성이 다른 유형별로 층화한다. 약품 목록과 사용기록의 연결률을 보고하고 연결되지 않은 코드를 조용히 삭제하지 않는다. 층별 목표 수와 동점 처리 규칙은 후보 수를 확인한 뒤 최종 평가 전에 설정 파일에 고정한다. 조건을 만족하는 품목이 부족하면 표본 수를 줄이고 범위를 보고한다.

최종 분석은 적격 품목 전체를 기본으로 하되 자원 제약에 따른 표본 연구라면 그 사실과 적용 가능한 모집단을 명시한다. 미래 자료에 기록이 존재하는지로 생존 품목만 선택하지 않는다. 평가 중 후속 기록이 없다는 이유만으로 단종을 추정하지 않는다. 담당자가 확인한 취급 종료와 추출 누락·미관측을 구분하고, 사전 종료 규칙과 제외 사유·커버리지를 기록한다.

서로 다른 단위·성분·규격의 약품 소모수량을 종류별로 더하지 않는다. 품목별 예측을 수행하고 종류별 동일가중 성과를 요약한다. 금액 또는 표준단위 합계는 변환 근거가 있을 때만 별도로 사용한다.

## 6. 보충 주기 분석

학습기간의 검증된 양수 입고 날짜에서 날짜 간격·요일 집중도·월중 날짜·기간별 변화·7/14/28일 후보 집중도를 산출한다. 구매 입고와 반납·반환 사건이 섞이면 분리한다. 분할 납품을 독립 주문으로 해석하지 않는다.

정기/비정기 판정 규칙과 최소 사건 수는 학습자료에서 결정하고 고정한다. 사건 수가 부족하거나 주기가 바뀌면 `판정 불충분` 또는 기간별 변화로 보고한다. 주문 자료가 없으면 결과명은 **입고·보충 간격**이다. 이 주기를 실제 발주 주기로 간주하지 않고, 시뮬레이션의 주기 후보를 정하는 탐색 근거로만 사용한다.

## 7. 예측 설계와 모델 튜닝

### 7.1 목표 및 공변량

주 목표는 사용기록에서 집계한 약품별 일별 소모수량이다. 수량 계약 `row_is_one_base_unit_v1`에 따라 각 행에 소모수량 1을 부여하고 의약품사용일시의 날짜와 약품코드로 합산한다. 예를 들어 동일 날짜·약품의 사용기록이 100행이면 해당 약품의 기본 단위 소모량은 100개다. 기본 단위는 연결 근거가 있는 정·캡슐·앰플·바이알 등으로 표시하며 미확인 코드는 기본 단위 미확인으로 남긴다. 실제 약품 공급·소모 기록의 예측이며, 결품으로 제공되지 못한 잠재 수요는 복원하지 않는다.

| 입력군 | 변수 후보 | 사용 조건 |
|---|---|---|
| 소모 이력 | 과거 1/7/14/28일 소모량, 과거 구간 평균·변동·양수 소모 빈도 | 정보 마감 이전 자료로만 계산. 불완전 구간을 평균으로 보완하지 않음 |
| 달력 | 요일, 월, 이미 공표된 공휴일 | 예측 시점에 확정된 값만 사용 |
| 정부 거리두기 정책 | 국가감염병_거리두기대응기간 Boolean | 공식 발표와 시행일·해제일을 분리. 당시 알려진 정책 상태·일정만 사용. §7.6 |
| 환자 활동 | 관측된 외래 방문자·신규 입원·재원·사용일 환자 수, 성별·연령 구분 | 집계 정의·대표성·당시 사용 가능 시점 확인 후 사용 |

사용일 환자 수를 공변량으로 만들 때 목표일의 약품 소비 행에서 계산한 환자 수를 같은 목표일 입력으로 사용하지 않는다. 같은 사용기록에서 생성된 환자 변수도 예측원점 이전에 확정된 값만 사용한다. 환자별 수량을 집계 후 그 환자를 중복 제거하여 목표수량을 줄이는 처리는 금지한다.

성별 전체·남녀 수처럼 중복된 정보를 동시에 넣는 경우 중요도 분산을 예상하고 변수군으로 해석한다. 전체 환자 규모의 효과와 구성비의 효과를 구분하려면 `전체 수 + 사전 지정 구성비` 조건을 추가하되 분모 0 처리·기타 성별을 명시한다. 실제 미래 환자 수·퇴원일·최종 진단·미래 입고·미래 재고는 주 모델 입력에서 제외한다.

### 7.2 실험 조건

| 실험 | 고정 조건 | 변경 조건 |
|---|---|---|
| E1 예측 모델 | 대상, 정보 컷오프, 원점, 기간, 소모 이력 | 계절 단순예측, SBA, ARIMA/SARIMA, XGBoost, TimesFM |
| E2 환자 정보 | 모델·달력·소모 특징 | 환자 활동 포함/제외, 사전 지정 변수군 제거 |
| E3 보충 성과 | 발주 정책·납기·포장·비용·서비스 목표 | 예측 모델. 같은 안전재고 설정 절차를 적용 |
| E4 주기 개선 | E3에서 고정한 모델과 기타 조건 | 주기 또는 재주문점 정책 |

E1의 순수 시계열 비교와 E2의 공변량 비교를 구분한다. 모델의 입력 지원 차이를 숨기지 않는다. ARIMA의 외생변수 비교는 SARIMAX 등 명시적 변형을 사용한다. 미래 외생변수가 필요하면 과거만 학습한 별도 환자 예측을 원점별 생성하며, 학습 예제의 환자 예측도 시간순 out-of-fold로 생성한다.

TimesFM은 먼저 고정된 사전학습 모델의 시계열 입력을 검증하고, 지원되는 과거 공변량 입력을 별도 비교한다. 3.0과 2.5는 서로 다른 실험 모델로 표시한다. 호환 실패 시 다른 버전 또는 다른 모델로 조용히 대체하지 않는다. 3.0의 직접 내려받은 가중치는 비상업·비운영 사용 라이선스이며 연구용 사용 조건을 확인한다. [공식 저장소](https://github.com/google-research/timesfm)

### 7.3 기간·원점·튜닝

| 구간 | 역할 |
|---|---|
| 2020-01-01–2022-12-31 | 초기 학습, 분류·후보·보충 주기 선정 |
| 2023-01-01–2023-06-30 | 시간순 rolling 내부 검증, 모델·특징·정책 후보 선택 |
| 2023-07-01–2023-12-31 | 고정 모델의 과거 순차 오차로 안전재고 보정, 정책 규칙 확정 |
| 2024-01-01–2024-12-31 | 계획 고정 후 최종 후향적 순차 평가 |

2024년은 이미 EDA에 사용했으므로 완전 미열람 holdout이 아니다. 최종 평가 전 설정·대상·주 지표를 고정하고 이후 변경은 새 버전의 탐색 실험으로 기록한다. 가능하면 2025년 이후 미확인 자료를 추가 검증으로 확보한다. Foundation model 공개 시점이 평가기간 이후임을 공개하고 2024년 당시 가용 모델 재현이라고 주장하지 않는다. 사전학습 데이터 노출 여부가 미확인이면 그 한계를 기록한다.

초기 기술 검증은 3–5품목·8개 과거 원점, 파일럿은 20–30품목·2023년 원점으로 진행한다. 공통 예측 비교는 매주 월요일 오전 원점과 1/7/14일 범위를 기본안으로 하며, 이는 계산을 위한 실험 일정이지 관측된 주문 일정이 아니다. E3/E4는 각 정책의 실제 의사결정 원점에서 예측하되 동일 수요 달력으로 성과를 비교한다. 보호기간이 더 길면 예측범위를 늘리고 동일 계약을 재검증한다.

보정기간을 기존 3개월 안에서 6개월로 확대한 이유는 보호기간 예측의 과거 오차 표본 확보다. 튜닝 예제와 검증 목표는 2023-06-30까지, 보정 예측의 전체 라벨은 2023-12-31까지 사용 가능해야 한다. 평가 종료 경계를 넘어서는 미완료 라벨은 제외한다.

주 분석의 학습 범위는 초기 시작일부터 확정 자료를 누적하는 Expanding window, 재학습 주기는 월 1회, 예측원점은 매주 월요일로 구분한다. 비교 분석은 같은 월별 재학습을 사용하는 최근 730일 창과 최초 적합 후 모수를 재추정하지 않는 모형이다. 비교 조건을 최종평가 전에 고정하고 2024년 결과로 주 분석을 바꾸지 않는다. 선택된 차수·특징·튜닝 규칙은 2023년 개발자료에서 정하고 2024년에서 변경하지 않는다. 최종 연말에 전체 목표 범위를 관측할 수 없는 예측은 범위별 공통 종료 규칙으로 제외하고 기록한다.

ARIMA/SARIMA는 제한된 차수·계절성 후보, XGBoost는 깊이·학습률·나무 수·정규화·과거 특징 후보, TimesFM은 문맥 길이·입력 방식·후처리 후보를 내부 검증한다. 각 모델의 후보 목록·시행 수·시간 상한은 합성자료 실행 후 최종 평가 전에 고정한다. 동일 시행 수가 동일 계산비용을 뜻하지 않으므로 모델별 실제 자원을 보고한다. XGBoost의 early stopping은 시간순 내부 검증만 사용한다.

음수 예측은 원본 예측을 보존하고 모든 모델에 동일한 `max(0, prediction)` 후처리를 적용한다. 오차는 원본·후처리 후 결과를 모두 저장하고 주 결과의 후처리 규칙을 고정한다. 포장단위 올림은 예측이 아니라 발주 단계에서만 적용한다.

### 7.4 예측원점·학습 창·재학습의 별도 계약

- **주 분석:** ARIMA·XGBoost는 월 첫 예측원점에서 그때까지 사용 가능한 자료로 다시 적합한다. 그 사이에는 모수를 유지하고 최신 과거 입력으로 주별 예측한다. 첫 달을 포함해 원점별 입력·학습 라벨의 가용성 컷오프를 지킨다.
- **상태와 입력 갱신:** ARIMA는 새 관측값으로 상태를 갱신하는 것과 모수 재추정을 구분한다. XGBoost는 매 예측원점에 과거 소모·환자 특징을 다시 계산하되 나무를 매주 추가 학습하지 않는다.
- **TimesFM:** 사전학습 가중치를 고정하고 각 원점의 최신 과거 문맥을 사용한다. 지원 문맥 길이와 입력 규칙은 개발기간에서 고정한다. 전체 누적자료로 재학습하는 ARIMA·XGBoost와 동일한 Expanding 적합이라고 표현하지 않는다.
- **튜닝과 재적합:** 2023년 7–12월 및 2024년의 고정 모델은 구조·하이퍼파라미터·재학습 규칙의 고정을 뜻한다. 월별 모수 재적합은 허용하며 전체 기간 동안 수치 모수를 고정한 실험과 구분한다.
- **평가 중 학습:** 2024년의 과거 실제값도 확정된 후에는 다음 재학습에 사용할 수 있다. 아직 관측되지 않은 목표일과 미완료 다일 라벨은 사용할 수 없다. 이는 순차 운영 재현이며 모든 2024년 라벨을 최초 학습에 포함하는 평가가 아니다.

### 7.5 선행연구에 근거한 코로나·구조 변화 처리

1. **주 분석에서 자료 보존:** 코로나 시기의 기록을 일괄 제거하거나 정상 수준으로 평균 대체하지 않는다. §2.1의 개입 시계열과 의료 수요 예측 사례를 근거로 실제 소모 경로를 유지한다.
2. **확인된 사건만 개입 변수로 사용:** §7.6의 정부 정책 Boolean을 기본 개입 변수로 정의한다. 병원의 코로나 병동 운영·병상 전환·진료 제한·정상화 날짜와 적용 시점이 추가로 확보되면 단계 지시변수 및 단계 내 경과시간을 SARIMAX·XGBoost의 별도 입력 조건으로 비교한다. 기본 ARIMA 및 TimesFM에 같은 외생변수 기능이 있다고 가정하지 않는다. 수요의 일시 충격과 지속적 수준·추세 변화를 구분하는 후보이지 인과 효과 추정이 아니다.
3. **예측 시점에 알려진 상태:** 미래 운영 상태가 미확정이면 실제 미래 상태를 입력하지 않는다. 현재 상태 지속 등 개발 단계에서 명시한 가정 또는 미사용 조건으로 평가한다. 2024년 전체 곡선을 보고 과거 변화점을 확정하여 모델 입력에 역적용하지 않는다.
4. **자료 제약:** 보유자료가 2020년에 시작하므로 충분한 코로나 이전 기준기간이 없다. Khan·BMJ 연구의 코로나 이전 추세 대비 반사실 ITS를 그대로 복제하거나 코로나의 인과적 소모량 효과를 추정하지 않는다. 코로나 여부만의 단일 0/1 변수는 학습자료에서 상태 변화가 없으면 효과를 학습할 수 없으며 이를 보정 완료라고 표현하지 않는다.
5. **성능의 구간별 보고:** 외부 운영 기록으로 구간을 확정하고 같은 예측·실제값에서 구간별 오차·편향·품목 수를 보고한다. 2020–2022년은 초기 학습구간이므로 적합 잔차를 2024년 예측오차와 비교하지 않는다. 초기 코로나 구간의 예측 성능이 필요하면 별도 과거 원점 실험으로 생성하고 주 평가와 분리한다. 운영 기록이 없으면 연도·분기별 보고만 하고 코로나 단계로 임의 명명하지 않는다.
6. **과거 자료 영향의 민감도:** Expanding과 최근 730일 창을 동일 원점·품목·월별 재학습으로 비교한다. 이것은 구조 변화에 대한 민감도이며 코로나 자료를 완전히 제거한 실험은 아니다. 코로나 이후만 학습하는 추가 분석은 정상화 기준과 학습 이력이 확보된 경우 고정된 별도 조건으로 수행하며, 해당 조건에서 불충분한 계절성·품목 커버리지를 보고한다.
7. **온라인 변화점 분석은 후속 조건:** Xu 논문을 근거로 원점까지의 관측만 쓰는 변화점 감시를 후속 확장으로 고려한다. 사후 전기간 탐지 결과로 재학습을 앞당기지 않는다. 이번 기본 모델 비교에 BOCD를 자동 추가하거나 코로나 종료일을 추정한 것으로 표시하지 않는다.

### 7.6 정부 발표 기반 국가감염병 거리두기 대응기간 변수

사용자 제안에 따라 특정 병원체명이 없는 정부 정책 기반 변수를 사용한다. 변수명은 **국가감염병_거리두기대응기간**, 저장 열은 `is_national_epidemic_distancing_response`로 정의한다. 감염병의 생물학적 발생·종식 자체를 관측한 변수가 아니라 정부가 거리두기 대응 정책을 운영하는 기간의 지표다. 감염병 위기경보나 감염병 분류 등급을 거리두기 시행과 같은 변수로 혼합하지 않는다.

| 항목 | 정의 |
|---|---|
| True / 1 | 정부의 국가 감염병 대응을 위한 사회적 거리두기 정책 체계가 운영되는 기간. 기본 정의는 생활 속 거리두기·완화·단계적 일상회복을 포함한 넓은 대응기간이며 제한 강도가 동일하다는 의미가 아님 |
| False / 0 | 해당 정책 체계 도입 전 또는 해제 후로 근거가 확인된 기간. 확진자 0명·감염병 종식·마스크 의무 해제를 뜻하지 않음 |
| 미확인 | 정책 기록의 누락·경계 또는 예측 시점 가용성이 미확인인 경우. False로 자동 대체하지 않고 확인 상태를 별도 보존 |
| 적용 범위 | 대한민국 정책 체계의 존속 여부. 지역별 제한 강도는 별도 변수이며 수도권 단계를 천안에 적용하지 않음 |
| 재사용 조건 | 이후 다른 감염병에도 동일한 공식 거리두기 정책 도입·해제 규칙을 적용할 수 있음. 새로운 감염병에서도 같은 약품 수요 효과가 나타난다는 보장은 아님 |

**현재 자료의 넓은 기간 정의:** [질병관리청 공개 보고서의 사회적 거리두기 절](https://www.kdca.go.kr/bbs/kdca/246/224138/download.do)은 2020-02-29 최초 도입과 2022-04-18 해제를 기록한다(PDF 파일 기준 194–195쪽 부근). [2022-04-15 정부 발표](https://www.korea.kr/briefing/policyBriefingView.do?newsId=148900782)는 2022-04-18부터 영업시간·사적모임 등 제한을 해제하고 마스크 의무는 유지한다고 밝혔다. 이 근거에 따라 사건일 기준 기본 Boolean은 **2020-02-29부터 2022-04-17까지 True, 2022-04-18부터 False**다. 초기 캠페인·생활 속 거리두기·일상회복을 포함하는 거친 정책 기간 정의임을 보고하며, 모든 날짜에 강한 법적 제한이 있었다고 해석하지 않는다. 2020-03-22는 강화된 거리두기의 시작이며 넓은 정책 체계의 최초 도입일과 구분한다. 정부 공식 [교육분야 브리핑](https://www.korea.kr/news/policyNewsView.do?newsId=156381742)이 강화 시행 시작을 설명한다.

**정보 누출 방지:** 사건일 기준의 사후 달력과 예측원점의 가용 정책 달력을 분리한다. 정책 테이블에는 `policy_id`, `jurisdiction`, `announced_at`, `effective_from`, `effective_to`, `source_url`, `definition_version`, `verification_status`를 저장한다. 과거 예측원점에는 `announced_at <= c(t)`인 발표만 전달한다. 나중에 나온 회고 보고서의 종료일을 그 발표 전 원점에 사용하지 않는다. 예를 들어 2022-04-15 해제 발표 전 예측에 4월 18일 해제 사실을 선반영하지 않으며, 발표 후 원점에서도 실제 공개 시각이 컷오프 이전인지 확인한다. 최초 도입·정책 변경의 당시 발표 원문과 시각은 정책 입력 생성 전에 추가 확인한다.

**미래 입력:** 발표된 시행·해제 일정은 그때의 정보로 목표일 정책 상태를 구성할 수 있다. 발표되지 않은 향후 연장·해제·새 감염병 발발을 실제 미래 정책표에서 가져오지 않는다. 미확정 목표일은 알려진 일정 준수·현재 상태 유지 등 사전에 명시한 정책 시나리오로 예측하고 관측 정책 상태와 구분해 저장한다. 미확정 시나리오를 실제로 알려진 미래 정보라고 표시하지 않는다.

**모델 비교:** XGBoost 및 SARIMAX에서 변수 포함/제외를 동일 품목·원점·학습 창·재학습 주기·튜닝 예산으로 비교한다. 모델 입력 명세에 Boolean과 환자 활동량의 역할을 구분한다. 기본 ARIMA의 외생변수 비교는 SARIMAX라는 별도 모델로 표시하고, TimesFM은 선택 버전의 지원 여부를 확인한 조건에만 정책 공변량을 추가한다. 미지원이면 미지원으로 보고한다.

**해석과 검증 범위:** 2023–2024년에는 위 기본 Boolean이 False이므로 해당 기간 평가는 거리두기 시행 중의 성능 또는 다음 감염병으로의 이전 가능성을 직접 검증하지 않는다. 시행 중 예측을 평가하려면 2020–2022년의 충분한 과거 이력이 있는 원점에서 별도 순차 실험을 설계하며 주 평가와 분리한다. False 구간이 짧거나 학습 표본에서 값이 상수이면 효과를 학습할 수 없는 상태를 보고한다. 연도·추세와 상관될 수 있으므로 변수 기여도는 예측 기여로만 해석한다. 지역 강도·경과일·해제 후 경과일 등 추가 변수는 Boolean 효과를 확인한 뒤 별도 계획으로 지정한다.

### 7.7 여러 날의 소모 이력과 모델별 입력 특징

예측원점의 날짜를 t, 약품 i의 일별 소모량을 y(i,t)라 한다. 첫 목표일은 t이며 최신 사용 가능 일자가 t−1인 경우 입력 이력은 `y(i,t−1), …, y(i,t−k)`다. 정보 반영이 하루보다 늦으면 t−1이 자동으로 가용하다고 가정하지 않고 정보 컷오프에 맞춰 최신 이력부터 구성한다.

**공통 자료부터 생성:** 원자료의 모든 사용 행을 수량 계약대로 세어 날짜·약품·기본 단위별 소모량과 관측 마스크를 만든다. 환자 활동량과 정부 정책은 별도 일별 테이블로 관리한다. 날짜·코드·단위·자료 가용시점 계약을 맞춘 뒤 각 모델의 입력 형태로 변환한다. 이 명세는 설계이며 약품 일별 집계·특징 행렬을 이미 생성한 상태라고 표시하지 않는다.

| 모델 | 입력 방식 | 선택하는 이력 관련 설정 |
|---|---|---|
| ARIMA/SARIMA | 확정된 과거 소모량의 순차 시계열을 입력. 지연·차분·오차 구조는 모형 차수로 정의 | p,d,q 및 주간 계절성 후보를 개발기간에서 선택. 모형의 AR 차수 p를 XGBoost의 특징 수 k 또는 Expanding 학습기간 길이와 동일하게 해석하지 않음 |
| XGBoost | `consumption_lag_1`부터 `consumption_lag_k`까지 명시적 열로 구성 | 기본 탐색안 k=28. k=7/14/28/56을 비교하고 k=1은 단일 지연 기준 조건으로 유지. 2023년 개발 원점에서 선택한 k를 최종평가 전에 고정 |
| TimesFM | 선택한 길이의 과거 소모 시계열을 문맥으로 입력. 지연값을 서로 다른 외생변수로 중복 주입하지 않음 | 문맥 길이 28/56/112일을 초기 후보로 둠. 지원 길이·최소 이력·자원 확인 후 개발기간에서 선택. 가중치는 고정하며 XGBoost의 k와 별도 기록 |

위 숫자는 주간 패턴의 1·2·4·8주 이력을 비교하기 위한 연구 후보이며 선행논문이 입증한 최적 길이가 아니다. 각 모델의 이력 길이는 명세와 결과에 공개한다. 서로 다른 입력 표현을 지원하므로 같은 컷오프·목표·평가 원점을 맞추고 특징 열 개수만 강제로 같게 만들지 않는다.

**비교 순서:** E1에서는 소모 이력만으로 예측한다. E2에서는 XGBoost·SARIMAX 및 지원되는 TimesFM 조건에 달력, 과거 환자 활동량, 국가감염병_거리두기대응기간을 단계적으로 추가한다. 환자 변수의 지연·집계 범위도 원점 이전에 한정하고 사용자 제공 수량 계약을 바꾸지 않는다. 추가 과거 합계·변동성은 별도 특징 후보로 지정할 수 있으나 원본값의 대체·평균 대입·평활화로 사용하지 않는다.

**다일 예측의 누출 방지:** 원점 t에서 t…t+13을 예측하면 모든 목표일의 소모 이력과 환자 입력은 원점 t의 컷오프에서 잘라야 한다. 7일 뒤 목표를 예측하면서 t…t+5의 실제 소모량을 지연값에 넣는 처리를 금지한다. 미래 요일·공휴일은 원점에 알려진 달력에서 구성하고 정부 정책은 원점까지 발표된 일정만 사용한다. 학습 예제도 당시 컷오프의 입력으로 구성하고 예측범위의 라벨이 완료된 예제만 적합에 사용한다.

**관측 범위:** 무기록은 자동 0 채우기 하지 않는다. 기본 연속 시계열 비교에서는 필요한 과거 구간이 완전 관측된 품목·원점만 사용하고 제외·이력 부족을 기록한다. 최대 후보 길이에 따른 공통 개발·평가 원점에서 이력 길이 효과를 비교하여 서로 다른 표본 구간 때문에 성능이 좋아 보이는 오류를 방지한다. 실험 중 누락 범위를 평균이나 다른 품목으로 채우지 않는다.

**입력 산출물:** `daily_drug_consumption.parquet`, `patient_activity.parquet`, 정책 테이블, `observation_masks.parquet`와 원점별 XGBoost 특징·라벨, ARIMA 학습 시계열 참조, TimesFM 문맥 참조를 저장한다. 원점·컷오프·각 입력의 마지막 관측일·라벨 종료일·열 순서·k/문맥 길이·정의 버전·원자료 해시를 manifest에 기록한다. 새 약품 입력은 기존 서송 고정 계약과 바로 연결하지 않고 반복 행 수량·관측 마스크·정책 가용성 검사를 먼저 통과해야 한다.

## 8. 변수 기여도 및 종류별 설명 분석

### 8.1 분석 방법

1. XGBoost에 대해 과거 학습자료로 고정한 배경 표본과 SHAP 설정을 사용한다.
2. 모델이 실제 순차 평가에서 생성한 예측의 SHAP 값을 설명한다. 목표값이나 미래 관측 환자 수를 설명 입력으로 추가하지 않는다.
3. 소모 이력·달력·환자 변수군을 하나씩 제외하고 같은 조건으로 재학습하여 오차와 물류 성과 차이를 측정한다. 주 제거 실험은 각 입력 조건을 동일한 내부 검증·튜닝 예산으로 다시 선택한 뒤 고정한다. 원래 모수 설정을 그대로 적용한 제거 실험은 별도 민감도로 표시한다.
4. 개별 환자 변수 제거는 사전 지정한 소수의 비교만 수행한다. 전체 평가 결과를 보고 변수·분류를 다시 선택하지 않는다.
5. 모델별로 동일한 변수군 제거 실험이 가능하면 비교한다. 지원되지 않으면 `미지원`으로 보고하고 XGBoost 중요도를 다른 모델의 중요도로 대신하지 않는다.

TreeSHAP은 음수 절단 전 원본 XGBoost 출력을 설명한다. 원본 출력의 가법성을 후처리된 max(0, prediction)에 그대로 적용하지 않는다. 절단 발생 원점과 변화량을 별도 저장한다. SHAP 평균 절댓값은 예측 기여도의 크기이며 영향 방향이나 인과 효과가 아니다. 방향은 원점별 부호·분포와 함께 보고한다. 상관된 변수는 중요도가 분산될 수 있으므로 개별 변수 순위와 변수군 제거 결과를 함께 제시한다.

주 변수군 제거 비교는 각 입력 조건을 같은 내부 튜닝 예산으로 선택하고 안전재고도 같은 절차로 각각 보정한다. 이는 해당 정보 없이 달성 가능한 예측·정책 성과다. 모수와 안전재고를 고정한 제거 비교는 별도 민감도로 표시한다. 종류별 설명 비교는 동일 품목·원점·범위·특징군의 공통 집합을 사용하고 범위 밖 원점은 커버리지로 보고한다.

### 8.2 종류별 집계

SHAP의 원래 값은 품목의 수량 규모에 영향을 받는다. 따라서 품목별 `mean(abs(SHAP))`와 품목 내 중요도 비율을 함께 저장한다. 종류별 주 요약은 품목 내 비율의 품목 동일가중 평균이며, 분모가 0인 품목은 미정의로 기록한다. 원래 크기와 비율이 다른 해석을 갖는다는 점을 보고한다.

종류별 결과에는 적격·성공·실패 품목 수, 정보 범위, 품목별 오차 변화, 변수군 제거에 따른 공급–재고 성과 변화를 함께 제시한다. 5개 미만 품목의 종류는 설명적 결과로 표시하고 강한 일반화를 하지 않는다. 다중 변수·종류 비교의 개수와 사전 지정/탐색 여부를 기록하며, 유의성 검정을 수행하면 다중비교 보정을 적용한다.

## 9. 미래정보 누출 통제

### 9.1 시간 계약

예측원점 `t`와 정보 마감 `c(t)`를 분리한다. 모든 입력·학습 라벨·분류 이력은 `available_at <= c(t)`여야 한다. 원점 t는 날짜 t의 오전 수요 발생 전 시각이다. 당일 d_t는 미관측이며 H일 예측 벡터는 t부터 t+H−1까지다. 보호기간 목표는 그 벡터의 해당 기간 합계다. 거래일이 과거라는 이유만으로 사용할 수 있는 자료라고 가정하지 않는다. 반영 지연이 확인되지 않으면 1/2/7일 지연 시나리오로 구분하고 결과는 해당 가정 아래의 성과로 표시한다.

| 누출 경로 | 통제 |
|---|---|
| 같은 사용기록으로 목표와 환자 공변량 생성 | 목표일 행의 성별·연령·환자 수를 목표일 입력에 사용하지 않음. 과거 마감 자료에서만 집계 |
| 당일 마감·미래 환자 정보 | 당시 관측된 값만 사용. 확정되지 않은 퇴원·진단·연령 갱신값 제외 |
| 이동통계·정규화 | 원점 이전 자료만 사용. 전체기간 평균·최대값·양방향 보완 금지 |
| 여러 날 합계 라벨 | 학습 예제의 라벨 종료와 사용 가능 시점이 컷오프 이전인지 검사 |

| 튜닝·SHAP 배경 표본 | 시간순 개발 구간에서만 선택 |
| 안전재고 | 실제 과거 원점에서 생성한 오차 중 현재 컷오프까지 확정된 것만 사용 |
| 초기재고·서비스 목표·납기·비용 | 평가 전에 고정. 시험구간의 최저 누적잔액으로 초기재고 역산 금지 |
| 미래 입고·재고 | 새 정책 시뮬레이션은 정책이 생성한 사건만 사용 |
| 시험 결과로 계획 변경 | 변경 전·후를 별도 실험 버전으로 보존 |

### 9.2 실행 전 필수 검사

- 미래 날짜의 사용기록·환자·소모량·입고 값을 변경해도 해당 원점의 입력과 예측이 같아야 한다.
- 전체자료에서 과거를 절단한 입력과 과거자료만 전달해 만든 입력이 같아야 한다.
- 입력과 학습 라벨의 최대 사용 가능 시점이 정보 컷오프를 넘지 않아야 한다.
- 14일 라벨 등 경계 중첩 예제는 미완료 라벨을 제거하고 purge 이유를 기록해야 한다.
- 안전재고·분류·환산·SHAP 배경 표본의 추정 범위도 동일하게 감사해야 한다.
- 모델 예측·평가 실제값은 품목·단위·원점·목표기간이 일치해야 한다.

이 검사가 통과하기 전에는 실제자료의 전체 모델 평가를 시작하지 않는다. TimesFM의 외부 사전학습 노출은 이 검사로 증명할 수 없으므로 별도 한계로 보고한다.

## 10. 물류 정책과 시뮬레이션

### 10.1 평가 단계의 구분

| 단계 | 주장 가능한 범위 |
|---|---|
| 약품 소모량 예측 평가 | 1행 1기본 단위 계약으로 집계한 소모수량 예측 성과 |
| 관측 소모량 재생 시뮬레이션 | 집계 소모량을 외생 수요로 둔 초기재고·납기·정책 가정 아래의 공급–재고 성과 |
| 실제 운영 재현 | 실재고·주문·납기·기존 정책이 확인된 범위의 후향적 운영 비교 |
| 도입 후 검증 | 별도 승인과 운영 자료로 실제 개선 확인. 본 계획의 즉시 실행 범위에 포함하지 않음 |

현재 실제 운영 재현은 진행 조건을 충족하지 못한다. 기록된 소모량이 미충족 잠재 수요를 포함하지 않을 수 있으며 예측 정책이 수요를 바꾸지 않는다고 가정한 실험임을 명시한다.

### 10.2 주기적 보충 정책

발주 주기 `R`, 납기 `L`, 포장단위 `b_i`, 재고위치 `IP`를 사용한다. 재고위치는 보유재고와 미입고 일반 주문량의 합이다. 기본 시나리오는 부족분을 당일 긴급조달하므로 이월 미충족 수요를 두지 않는다.

```text
S(i,t) = 향후 R+L 동안의 예측 소모 합계 + 안전재고
Q(i,t) = b_i × ceil(max(0, S(i,t) − IP(i,t)) / b_i)
```

주문은 날짜 t+L 시작에 도착하며 다음 주기 주문은 t+R+L 시작에 도착한다. 보호기간은 **t부터 t+R+L−1까지**다. 일별 예측을 합산하고 이미 미입고 상태인 일반 주문을 재고위치에 포함한다.

안전재고 후보는 과거 순차 예측의 총수요 오차 e = 실제 보호기간 소모합 − 예측합에 대해 `SS(alpha) = max(0, empirical_quantile(e, alpha, method="higher"))`로 정의한다. alpha 후보는 0.80/0.90/0.95/0.975/0.99이며 경험적 버퍼 후보일 뿐 수량 충족률 또는 보장된 분위수 coverage가 아니다. 소표본 극단 분위수의 불안정성을 보고하고 최종평가에서 후보를 추가하지 않는다.

기본 표본 통과 조건은 전체 목표가 관측된 과거 오차 30개 이상과 목표기간이 겹치지 않는 구간 8개 이상이다. 보정 예측은 하루 간격으로 생성하되 중첩 표본을 독립 표본으로 세지 않는다. 조건을 만족하지 못하는 긴 보호기간 정책은 미선정으로 기록한다. 필요하면 2024년 결과를 보기 전에 더 이른 개발·보정 기간을 사용하는 새 계획 버전으로 재설계한다. 다른 품목의 오차로 부족분을 조용히 보완하지 않는다.

보정기간에도 각 원점의 정보 컷오프까지 완료·사용 가능한 과거 오차만으로 alpha별 버퍼를 계산한다. 7–12월 전체 오차를 앞선 날짜의 버퍼에 역적용하지 않는다. 각 후보는 이 규칙으로 순차 정책 경로를 실행하며, 필요한 표본 수를 모두 충족하는 품목·모델의 공통 시작일을 과거 정보로 정한다. 후보별 같은 초기상태·같은 평가일을 사용한다. 보정 정책 평가에 최소 30개의 공통 관측일이 남아야 한다. 이력이 부족하거나 평가일이 짧은 긴 보호기간은 미선정으로 기록한다.

그 경로의 공급 목표 통과 후보 중 평균 재고가 최소인 alpha를 선택한다. 동점은 긴급조달량, 발주 횟수, 작은 alpha 순으로 해결한다. 충족 후보가 없으면 `no_feasible_calibration_policy`다. 보정 성과는 후보 선택 근거이며 독립 최종 성과가 아니다. 최종평가에서는 첫 원점 c(t0)까지 완료·사용 가능한 보정 오차로 선택 alpha의 버퍼를 한 번 계산하여 고정한다. 실제값·오차·보정 정책 성과·alpha 선택 모두 c(t0)까지 사용 가능해야 한다. 마지막 2023년 기록도 전산 반영이 늦으면 제외한다. 비정기 `(s,S)` 후보에도 같은 규칙을 적용한다.

### 10.3 하루 사건 순서

1. 예정 일반 주문 도착 반영.
2. 입고 후 재고와 과거 정보 컷오프를 사용해 오전 주문 결정.
3. 해당 날짜 수요 발생 및 일반재고 공급.
4. 부족량을 당일 긴급조달하여 공급.
5. 재고 마감, 비용·사건 저장.

납기는 기본적으로 1일 이상이다. 당일 도착이나 주말 비운영은 별도 명세를 가진 시나리오다. 오전에 주문을 정하면서 당일 수요를 보는 오류를 금지한다. 일반재고 충족률과 긴급조달 포함 충족률을 분리한다. 음수 보유재고·긴급조달과 이월 부족의 이중 계산을 금지한다.

### 10.4 초기상태와 종료상태

주 분석은 2024-01-01 오전의 동일 초기재고와 미입고 주문 0에서 시작한다. 공통 초기재고는 2023년 중 첫 평가 원점 c(t0)까지 전체 값이 사용 가능하고 완전 관측된 H_ref일 소모합의 경험적 0.90 분위수를 포장단위로 올림한 값으로 정의한다. H_ref는 주 정책의 기준 R+L로 개발단계에서 고정하며 모델별로 바꾸지 않는다. 과거 표본이 부족하면 주 재고 실험은 보류한다. 이 값은 관측 실재고가 아니라 비교용 가정이다.

초기재고 0 및 공통 초기재고의 0.5배/2배는 민감도로 사용한다. 정책별 준비기간은 별도 민감도이며 2023년 보정기간을 재생한다. 준비기간 비용은 2024년 주 지표에 합치지 않고 별도 보고하고, 시작일·끝일·초기값과 평가 시작의 정책별 보유재고·미입고 상태를 공개한다. 준비기간 후 상태가 같다고 주장하지 않는다. 초기재고·준비기간 설정에 2024년 값을 사용하지 않았는지 검사한다.

모든 정책은 연말에도 동일한 정상 발주 규칙을 계속 사용하며 미래 평가 종료를 알고 주문을 줄이지 않는다. 기말 보유재고·미입고 주문량을 보고한다. 구매비용을 포함하면 동일한 잔여재고 평가·미입고 주문 처리 규칙을 적용하고 민감도를 제시한다. 초기·종료 상태에 의해 정책 순위가 바뀌는지 확인한다.

납기·포장·서비스 목표·비용은 실제값 확보 여부를 표시한다. 미확인 조건의 시나리오 목록과 수치를 개발 단계에서 정하고 시험평가 전에 동결한다. 실제 구매 주문자료가 없으면 기존 병원 운영을 기준선이라고 부르지 않고 **기준선 예측을 사용한 모의 정책**과 비교한다.

## 11. 평가 지표와 통계 분석

### 11.1 예측 지표

- MAE: 품목·범위별 보고. 종류 간 서로 다른 단위의 MAE를 그대로 평균하지 않는다.
- MASE: 학습자료의 계절 단순예측 오차로 척도화. 분모 0은 미정의로 저장하며 별도 MAE·커버리지 보고.
- 과소·과대 예측 편향과 보호기간 총수요 오차.
- SPEC: 사전 고정한 과잉·부족 가중치의 보조 지표. 물류 비용 또는 실제 재고와 동일시하지 않음.

주 예측 비교는 품목별 MASE의 동일가중 요약과 기준선 대비 대응 오차 차이다. 품목 중요도·거래규모 가중 결과는 학습기간에서 고정한 가중치를 사용한 보조 분석으로 분리한다. 0이 많은 수요에서 MAPE를 주 지표로 사용하지 않는다.

### 11.2 물류 지표

일반재고 즉시 충족률을 다음과 같이 정의한다.

```text
FillRate_i = 1 − sum(일반재고 부족수량_i) / sum(수요_i)
```

수요 합계가 0인 품목은 충족률이 미정의이며 제외 품목 수를 보고한다. 주 전체 요약은 품목별 충족률의 동일가중 평균과 목표 달성 품목 비율이다. 중요도 가중 평균은 개발·업무 근거로 고정한 무차원 가중치를 사용하는 보조 분석이다. 서로 다른 단위의 수요·부족량을 직접 합산하지 않는다. 전체 수량 비율은 공통 단위가 확인된 집합에서만 보고한다. 의료용 서비스 목표는 담당자 확인이 필요하며, 확인 전 목표 수준은 임상 권고가 아닌 시나리오 값이다.

품목별 평균 마감재고, 최대재고, 부족 발생일, 긴급조달량, 발주 횟수, 기말재고·미입고 주문량을 보고한다. 주 운영 비교는 **보정 구간에서 선정·고정한 정책의 평균 재고 변화와 2024년 공급 목표 달성 여부**다. 2024년에서 목표를 만족한 후보를 새로 고르지 않는다. 목표 미달도 전체 표에 포함하며, 미달 품목을 제거한 재고 개선만으로 전체 효율화를 주장하지 않는다. 주기 변경 실험에서는 발주 횟수를 함께 비교한다. 계수 없이 하나의 임의 효율화 점수로 합치지 않는다.

### 11.3 비용과 개선율

```text
C = sum_i,t [h_i × 마감재고_i,t
             + K_i × 1(발주_i,t > 0)
             + e_i × 당일 긴급조달수량_i,t]
CostReduction(%) = 100 × (C_baseline − C_model) / C_baseline
```

`h_i`는 단위·일당 보유비용, `K_i`는 발주 1회 비용, `e_i`는 긴급조달 추가비용이다. 위 공식은 본 연구의 기본 시나리오 정의이며 특정 논문의 원문 공식이 아니다. 공동 구매라면 주문 묶음별 비용이 필요하며 현재 품목별 식으로 실제 공동발주 절감을 주장하지 않는다. 일반 구매비용·폐기비용은 자료와 종료 상태 처리 규칙이 확보된 확장 모형에서만 포함한다.

비용 미확인 시 금액 절감은 보고하지 않고 비용계수 민감도와 물량 지표를 제시한다. 기준 비용·평균 재고가 0이면 상대 개선율을 계산하지 않고 절대 차이를 보고한다. 비용 최적 정책 선정은 보정 구간의 공급 목표 통과 후보 안에서만 수행한다. 최종평가에서는 선정 정책의 비용과 목표 미달 여부를 그대로 보고한다. 같은 목표가 같은 실제 충족률을 뜻하지 않으므로 재고–충족률 곡선과 달성률을 함께 비교한다. 시험기간 곡선은 설명용이며 시험결과에서 다시 선택한 후보를 주 결과로 삼지 않는다.

### 11.4 불확실성·실패·선정 편향

예측원점·목표기간이 겹치므로 행을 독립 표본으로 취급하지 않는다. 동일 날짜·품목의 대응 차이에 대해 시간 블록 bootstrap을 사용한다. 블록 길이·반복 수는 개발자료에서 고정하고 예측범위·보호기간 중첩을 반영한다. 정책 비교는 일별 전체 사건 경로를 생성한 후 지표를 계산하며, 재고 상태를 무시해 수요 날짜를 섞지 않는다. 복제 실험이 필요하면 전체 정책 경로를 다시 실행한다.

모델 seed 변동과 시간 표본 변동을 분리한다. 종류별 표본 수·실패 수와 다중비교 처리 방식을 제시한다. 공통 성공 품목·원점의 대응 비교와 각 모델 전체 적용 범위를 함께 보고한다. 실패를 제거하여 성과만 좋아 보이게 만들지 않는다. 자동 legacy/naive 대체를 금지한다.

## 12. 구현 가능성과 검증 범위

현재 환경은 Apple Silicon macOS이며 PyTorch MPS 사용 가능, CUDA 미사용이다. XGBoost·PyArrow는 설치되어 있고 `statsmodels`, `timesfm`, `timesfm3`는 현재 미설치다. TimesFM의 실제 장치 호환·처리시간·메모리 사용은 미검증이다.

개발은 Python을 기본으로 한다. 기존 `paper_code/forecasting/`의 시간 절단·명시적 오류·예측 정렬 원칙을 재사용한다. 기존 환자/처방 계약·월요일 일정·연속 일별 비음수 입력은 이번 약품 수량 계약과 동일한지 확인하고 연결한다. 약품 소모 목표, 관측 마스크, 사용 가능 시점, 임의 정책 원점을 명시하는 인터페이스를 별도로 설계한다.

ARIMA·TimesFM은 합성자료로 설치·호환을 확인하고 3–5품목에서 작은 경로를 실행한 후 확장한다. TimesFM의 버전·체크포인트·라이선스·장치·추론 설정을 고정한다. 시간·메모리 상한을 넘으면 결과를 실패 또는 미실행으로 기록한다. 다른 실행환경을 쓰려면 승인된 저장소 내 처리와 자료 접근 규칙을 먼저 확정하며 병원 원자료를 외부 API로 전송하지 않는다.

구현 후 검증은 모듈 컴파일, 집중 동작 테스트, 패키지 validator, 누출 불변성 검사, 데이터 열·날짜·단위·수지 검증을 포함한다. 기존 validator 통과가 새 천안의료원 모델의 타당성을 검증한 것은 아니므로 새 검증 범위를 명시한다.

| 적합 모형 | 원점별 ARIMA 적합 상태·XGBoost 모델·특징 명세/열 순서·전처리 상태·라벨 종료·입력 및 artifact 해시. 실제 적합 완료 시각과 역사적 데이터 컷오프를 구분 |

환자 식별자는 집계 과정 내부에만 유지하고 최종 예측·보고 테이블에 저장하지 않는다. 환자 집계·품목 운영량도 민감할 수 있으므로 내부 산출물과 외부 배포본을 분리한다. 현재 `data/processed/cheonan/`과 `models/cheonan/logistics/`, `results/cheonan/logistics/`, `reports/cheonan/logistics/`는 Git 제외되어 있다. 새 출력 경로도 실행 전 제외 규칙을 확인한다. 적합 모형도 학습자료 정보를 포함할 수 있으므로 내부 산출물로 관리한다. 원자료 또는 개인 식별값을 외부로 업로드하지 않는다.

TimesFM은 공개 가중치 식별자·해시·버전·추론 설정을 model_manifest에 연결한다. 가중치 보존 방식은 라이선스 조건을 따르고, 적합 모형과 SHAP에 필요한 원점별 특징·전처리 상태를 내부 저장한다.

## 16. 연구의 한계와 기대 산출물

기대 산출물은 약품 소모수량 시계열, 약품 분류와 보충 주기 설명, 재현 가능한 모델 비교, 환자 변수의 추가 가치, 종류별 예측 기여도, 공급 수준을 고려한 보충 정책 평가다. 비용 또는 재고 감소를 사전에 확정된 결과로 가정하지 않는다.

현재 핵심 한계는 약품 단위·코드 연결 범위와 취소·반납·정정 처리, 무기록 날짜·관측 지연 및 실제 재고·주문·잠재 수요의 미확인이다. 1행 1기본 단위는 사용자 제공 업무 기준이며 원자료의 수량 열 또는 병원 공식 확인 문서로 독립 검증한 결과라고 표현하지 않는다. 종류별 중요도는 관측된 공변량과 해당 모델에 한정되며, 환자정보가 병원 전체 활동을 대표하지 않을 수 있다. 2024년 자료를 본 상태에서 계획을 수립했으므로 사전등록 연구라고 표현하지 않는다. 후속 미확인 기간 검증이 없으면 후향적 사례 연구의 범위로 해석한다.

## 17. 독립 검토 및 변경 이력

**검토 범위 구분:** 아래 독립 검토는 물품 출고를 주 대상으로 한 [v1.0 보존본](RESEARCH_PROPOSAL_v1.0.md)에 관한 기록이다. v1.1의 약품 소모수량 계약·대상 변경과 v1.2의 코로나 근거·재학습 설계 및 v1.3의 정부 정책 변수·v1.4의 지연 특징 설계는 사용자 지시에 따른 수정이며 새 독립 검토나 모델 실행 검증을 완료한 것으로 표시하지 않는다.

새 독립 Agent는 문서 전체를 검토하여 **조건부 타당**으로 판정하고 높은 우선순위 2개와 중간 우선순위 5개의 보완점을 제시했다. [독립 검토 및 반영 기록](RESEARCH_PROPOSAL_REVIEW.md)에 쟁점·수정·남은 조건을 기록한다. v0.2 재검토는 기존 7개 쟁점의 해소를 확인했고 보정 버퍼의 시간 계약 모순 1개를 추가 지적했다. v0.3에서 보정 중 원점별 과거 오차 사용 및 최종 첫 원점의 가용성 컷오프를 반영하여 추가 확인을 받았다. 최종 검토는 마지막 시간 계약 모순이 해소되었고 확인 범위에서 새로운 높은 우선순위 문제나 치명적 오류가 없다고 판정했다. 자료 의미·가용시점 확인, 사전 결정표 동결, 모델 호환·누출 검사 통과는 실행 조건으로 남는다. 검토의 통과는 실제 모델 성능·운영 적용·윤리 승인 확인을 의미하지 않는다.

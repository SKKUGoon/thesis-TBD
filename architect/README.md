# TimesFM 주간 예측과 가상 주문 시스템 설계

설계 버전 0.3 · 작성일 2026-10-21 · 상태: 상세 명세와 Linux ARM64 가상 시스템 구현

마감된 월요일부터 일요일까지의 일별 자료를 매주 받아 다음 월요일부터 14일을 예측한다. 예측과 재고·미입고 주문·납기로 주문안을 만들고, 담당자의 명시적인 Yes 이후에만 가상 공급처로 주문한다. 이 설계는 병원 한 곳·창고 한 곳의 비상업적 가상 연구·평가를 대상으로 한다.

중앙 RabbitMQ가 작업·완료 알림·로그를 전달한다. TimesFM과 업무 모듈은 담당 PostgreSQL 테이블에 직접 접근한다. 독립 로거도 같은 PostgreSQL의 별도 로그 테이블에 기록한다. 업무 상태는 DB가 기준이며 DB 변경과 다음 작업은 Outbox로 연결한다.

Linux CPU에서 실제 TimesFM 실행과 가상 주간 수신·주문 승인·입고를 구현했다. 실행·장애·복원 검증과 미검증 경계는 [8단계 구현 기록](08_IMPLEMENTATION.md), 설치·실행은 [배포 안내](../deploy/README.md)를 따른다. 아래 1~7단계는 설계 당시 정책이며 각 문서의 과거 미구현 표기와 현재 실행 상태를 구분한다.

## 독립 검토 반영

2026-10-21 독립 검토는 대화 이력을 전달하지 않은 에이전트에 현재 구조와 업무 조건만 제공하여 수행했다. 검토 에이전트는 메모리·과거 세션·프로젝트 파일을 읽지 않았다고 보고했으며 공식 문서와 설계를 비교했다. 판단은 조건부 적합이었다. 코드·부하·서버 이식성의 실증 검사는 수행하지 않았다.

| 검토 사항 | 반영 문서 |
|---|---|
| 단일 Compose·공유 DB·독립 ML 유지 | [1단계](01_SYSTEM_ARCHITECTURE.md) |
| 입력 정정·관측시각·불변 입력 | [2단계](02_DATA_PIPELINE.md) |
| DB·메시지 이중 쓰기와 중복 전달 | [3단계](03_MESSAGE_DELIVERY.md) |
| 승인 경쟁·불명 주문·부분 입고 | [4단계](04_FORECAST_AND_ORDER.md) |
| 큐 기반 로거·같은 DB의 공통 장애 | [5단계](05_LOGGING.md) |
| 최소 권한·역할별 쓰기 소유권 | [6단계](06_API_DATABASE_CONTRACTS.md) |
| 버전 고정·복구·자원·완료 기준 | [7단계](07_DEPLOYMENT_VALIDATION.md) |

기술 로그는 제한된 유실을 허용하지만 승인·주문·입고 이력은 DB에 보존한다. 애플리케이션 로그를 로컬 파일로 우회 저장하는 경로는 추가하지 않는다. 큐 용량·보존기간·재시도 간격은 가상 평가용 기본값이며 측정된 처리량이나 서비스 수준이 아니다.

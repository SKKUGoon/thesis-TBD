# 예측 결과 재생 데모 v0.1 — 확정


2026-11-03 사용자가 현재 방식을 데모 버전으로 확정했다. 웹·경량 API 두 컨테이너, 읽기 전용 예측/집계 시드, SQLite 영속 상태를 기본 배포 방식으로 유지한다. 실제 모델 추론과 병원 운영 연동은 이 버전의 범위에 포함하지 않는다. 소스·설정·합성 테스트만 공개 Git에 보존하고 사설 시드·DB·토큰·실행 묶음은 별도로 관리한다.

## 구현 계획과 검토

- 기존 확정 대시보드를 공유하고 데모 전용 API를 분리한다. 기존 PostgreSQL·브로커·실제 TimesFM 경로는 변경하지 않는다.
- 서버 구성은 웹 Nginx와 Python API 두 컨테이너다. 상태·요청 중복 방지·처리 이력은 SQLite 볼륨에 원자적으로 저장한다.
- 동결된 천안의료원 30품목의 기존 joint 평가 예측을 날짜·품목별로 보존한다. 예측 원점은 이동시키지 않으며 실제값은 원점 전날까지만 반환한다.
- 시작 날짜는 시드에 있는 주별 원점에서만 선택한다. 로딩 시간은 서버가 검증하고 완료 예정시각을 영속화한다. 재시작·재요청으로 주차가 중복 진행되지 않는다.
- Demo Setting은 관리자 설정 안에서만 표시한다. 일반 대시보드에 데모 배너를 추가하지 않는다. API provenance와 이 문서에는 재생임을 기록한다.
- 실재고·포장·납기가 없는 상태를 유지한다. 이번 범위는 예측 시연과 서버 이전이며 실제 주문량을 만들지 않는다.

검토: 임의 날짜 이동, 무기록 0 대입, 브라우저만의 타이머, 모델 체크포인트 포함, 원자료 포함을 배제한다. 별도 에이전트 검토는 수행하지 않았으며 구현 후 API·브라우저·패키지 검증 결과를 기록한다.

## 완료와 검증 (2026-11-02)

- 최종 묶음: `runs/cheonan/portable_demo_20261102_final/bundle.tar.gz` (1,665,868 bytes). 파일별 manifest는 묶음 안에 보존한다.
- 시드: 2024-01-01–2024-12-16, 51원점·30품목·21,420예측. 해당 예측 원장의 관측 실제값을 등록된 사용·출고 집계와 전수 대조했다. 코호트 20261008_01과 _02의 채널·원천키·이름·단위도 일치한다.
- 관리자 설정 → Demo Setting: 시작 원점과 0–600초 로딩 시간. 파일 설정은 빈 볼륨 최초 기동에만 적용하고 이후 변경은 SQLite에 보존한다. 적용 시 새 업무를 열며 이전 업무를 보존한다.
- 서버 구성: Nginx 정적 화면 + Python/FastAPI·SQLite. 브로커를 사용하는 기존 운영 스택과 별도인 재생 전용 경로다. 웹도 로컬에서 빌드하여 서버 Node.js·npm 빌드를 제거했다.
- 검증: Python API 9개, 기존 프론트 도메인 2개, 실제 브라우저 흐름 1개 통과. Linux ARM64 Docker 빌드·기동·처리 대기 중 API 재시작 후 설정·작업 보존을 확인했다.
- 최종 묶음 17파일 SHA-256 대조 및 압축 내 시드 존재·토큰/체크포인트/원자료 부재를 확인했다. 토큰은 서버 준비 시 새로 생성한다.
- 최종 브라우저 증거는 위 실행 폴더의 `browser/01-dashboard.png`부터 `05-mobile.png`까지다. 초기 선택기 접근성 라벨 오류의 실패 기록은 `portable_demo_20261102_02/`에 보존하고 수정 후 _04·_05·final에서 통과했다.
- 메모리 단회 관측: API 41.8MiB·웹 4.965MiB. 부하·장기 서비스 수준 검증은 아니다. 실제 대상 서버와 AMD64 실행은 확인하지 않았다.

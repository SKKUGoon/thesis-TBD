## 주간 제출과 가상 시간 정책

1. 업무 주간은 `Asia/Seoul` 월요일 00:00 이상 다음 월요일 00:00 미만이다. 자료에는 일요일 전체가 마감되어 있다는 선언을 포함한다.
2. 제출 원본에 `week_start`, `week_end_exclusive`, `source_closed_at`, `source_available_at`, `received_at`, `schema_version`, `source_revision`, 파일별 SHA-256을 연결한다. 서버 수신시각을 사건일로 사용하지 않는다.
3. 미래 예측 원점은 해당 주간 다음 월요일 00:00이다. `forecast_origin`, `generated_at`, `decision_as_of`를 각각 보존한다. 늦게 생성된 예측을 원점 당시 존재한 예측으로 표시하지 않는다.
4. 초기 가상 시나리오는 다음 월요일 00:00에 자료가 가용해지는 것으로 정한다. 추론 완료 이후 동일 가상일의 첫 수요 처리 전에 승인·발주한다. 당일 수요 이전에 처리가 끝나지 않는 시나리오는 지연 상태로 분리한다.
5. 테스트 버튼은 서버가 관리하는 시나리오의 다음 주간을 제출한다. 재시도·중복 클릭은 동일 제출을 반환하고, 명시적으로 새 주간을 요청할 때만 가상 시간을 진행한다.
6. 가상 시간은 업무 사건의 순서와 납기에 사용한다. 실제 UTC 시각은 API 수신·처리시간·작업 lease·heartbeat에 사용한다. 클라이언트가 운영 시각을 임의 변경하지 못한다.
7. 정기 실행은 같은 제출·검증 경로를 사용한다. 초기에는 테스트 버튼으로 진행하며 별도 스케줄러 제품을 추가하지 않는다.

첫 실행 전에 112일 이상의 가상 이력을 준비한다. 초기 이력 적재는 주간 신규 제출과 구분한 bootstrap 작업으로 기록한다. 이후 최소 6주를 순서대로 진행한다. 원자료·다른 병원 데이터·연구 예측은 가상 시나리오와 섞지 않는다.

## 입력 확정과 데이터 정정 정책

주간 제출은 일별 환자 집계·약품 사용기록 수량·물품 기록 출고량·재고 기준시각·미입고 주문을 포함한다. 주간 총합만으로는 일별 모델 입력 계약을 충족하지 못한다. 환자 식별값은 수신하지 않고 기존 69채널과 같은 집계 의미를 유지한다.

- 반복된 실제 사용기록은 모두 센다. 제출 중복 제거는 제출 식별자·해시·원천 사건 키로 수행하며, 값이 같은 행이라는 이유로 삭제하지 않는다.
- 관측된 0, 미관측, 해당 없음의 상태를 구분한다. 필수 파일이 누락되면 제출을 반려한다. 과거 모델 입력의 개별 미관측값은 원래 관측 마스크로 보존하고, 입력 적격성 검사를 별도로 수행한다.
- 품목·날짜·단위·채널 순서·환자 집계 정의·필수 달력·추출 범위를 검사한다. 품목별 약품 기본 단위·물품 출고 단위·발주 포장 환산을 별도로 기록한다.
- 검증 완료 시 모든 입력의 버전과 해시를 묶은 `input_snapshot_id`를 확정한다. DB의 불변 revision 행 또는 그 행을 연결한 불변 manifest로 구성한다. 상태가 `sealed`가 되기 전 추론하지 않는다.
- Snapshot 확정은 짧은 일관된 트랜잭션 안에서 수행한다. 봉인 이후 목표·환자·달력·품목 순서를 수정하지 않는다. TimesFM은 봉인된 식별자만 조회하며 긴 추론 중 DB 트랜잭션을 열어두지 않는다.
- 정정 제출은 `supersedes_delivery_id`와 새 revision을 갖는다. 기존 실행·입력·예측은 보존한다. 아직 승인되지 않은 관련 주문안은 대체·만료시키며, 이미 전송 중이거나 접수된 주문은 자동 취소·대체하지 않는다.
- 원본 파일을 임시 위치에 완전히 저장·해시 검증한 후 불변 위치로 확정하고 DB 접수를 커밋한다. DB 접수 실패로 남은 고아 파일은 유예기간 후 참조 여부를 확인하여 정리한다. DB가 가리키는 파일이 없거나 해시가 다르면 실패로 처리한다.

일반적인 PostgreSQL Read Committed에서 연속 조회가 같은 snapshot을 보장하지 않는다는 점을 고려해 불변 입력 버전을 사용한다. [PostgreSQL 격리 수준](https://www.postgresql.org/docs/current/transaction-iso.html)

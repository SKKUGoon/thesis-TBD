# 11단계 실제 품목·사용 기록 연결과 예측 이력 비교

구현 버전 0.1 · 2026-10-22

기본 프론트엔드를 실제 천안의료원 보유 품목·사용 기록을 읽는 업무로 전환했다. 이름만 실제 제품으로 바꾼 테스트 수량을 사용하지 않는다. 기존 생성 데이터 scope는 보존하되 기본 화면의 선택·결과에서 제외한다. 보유 자료가 2020–2024년이므로 화면에는 연도를 포함한 기록 기준일을 표시하며, 현재 시점의 실시간 병원 자료로 표현하지 않는다.

## 실제 자료와 처리

- 동결된 2020–2022년 선정 코호트의 약품 20개·물품 10개 이름·단위·제품 연결을 그대로 사용한다. 약품 첫 품목은 타세놀이알650mg서방정 8시간이다.
- `data/processed/cheonan/analysis/timesfm_cohorts_20261008_02/`의 `frozen_cohorts.parquet`, `daily_targets.parquet`와 `patient_standard_20261007_02/daily_patient_composition.parquet`만 읽는다. 환자 개별 행이나 식별자를 내보내지 않는다.
- `deploy/prepare_records.py`가 품목 정보와 일별 30개 목표·69개 환자 집계를 사설 읽기 전용 JSON에 등록한다. 1,827일·30채널의 무기록 8,556개는 null로 보존한다. 기존 manifest의 두 입력 해시를 확인하고 환자 집계 파일의 해시도 기록한다. 원본 Parquet는 수정하지 않는다.
- `cheonan_records_v1` 업무는 이 데이터의 해당 마감 주간만 전달한다. 실제 수량을 재고 부족에 맞춰 줄이거나 난수로 만들지 않는다. 원점 이전 112일/56일 목표와 환자 마지막 28일, 알려진 달력 입력을 기존 Linux TimesFM에 전달한다.
- 자료 가용시각은 사용자가 지정한 주간 마감 시점으로 재현한다. 원자료의 당시 공개시각을 확인했다는 뜻은 아니다. 연구의 후향적 재현이며 과거 실제 운영 시점에 예측이 발행되었다는 주장이 아니다.

## 실제 재고와 주문 경계

현재 연결한 자료는 사용 기록·물품 기록 출고량이며 실제 재고 스냅샷·포장 단위·납기 자료가 아니다. 실제 자료 업무에는 임의의 140개 재고, 10개 포장, 1일 납기, 테스트 공급처를 생성하지 않는다. 재고 테이블은 비어 있고 화면은 미등록으로 표시한다.

주간 입력의 inventory=null은 실제 자료 프로필에서만 허용한다. 다른 기존 프로필은 여전히 완전한 재고 입력을 요구한다. 실제 자료 프로필에서는 재고·발주 조건을 등록하기 전 주문안·공급처 주문을 생성하지 않는다. 예측은 재고 미등록 상태에서도 실행하고 비교할 수 있다. 실재고와 주문 조건의 등록 기능은 해당 자료 확인 후 별도로 연결한다. 이전 10단계의 생성 자료 주문·입고 검사를 실제 재고 검증으로 재해석하지 않는다.

## 예측 비교 API와 그래프

`GET /api/v1/items/{item_id}/forecast-history?forecast_id={id}`를 추가했다. 기존 Bearer·scope·viewer 검증과 RLS를 그대로 사용한다. 현재 예측, 동일 범위의 직전 유효 원점 예측, 현재 원점 이전에 접수·검증·가용한 실제값을 반환한다. 날짜별 수량은 기존 정확 소수 문자열이다.

- 짙은 실선: 실제 사용량 또는 물품 기록 출고량. 미관측은 선을 끊고 0으로 채우지 않는다.
- 회색 점선: 이전 원점의 14일 예측. 이번 예측과 겹치는 미래 대상일도 그대로 남겨 변경을 비교한다.
- 파란 실선: 이번 원점의 다음 14일 예측.
- 회색 음영: 이전 예측에서 실제값을 확인할 수 있는 기간.
- 청색 음영: 이번 예측 기간. 확률 신뢰구간으로 표시하지 않는다.
- 그래프 안의 MAE·WAPE와 관측일 수: 직전 예측과 관측 실제값의 날짜 교집합만 사용한다. 미래 실제값을 반환하거나 오차에 넣지 않는다. 표본이 없으면 오차는 null이고 실제값 합계가 0이면 WAPE는 null이다.

MAE = Σ|예측−실제| / 관측일 수. WAPE(%) = 100 × Σ|예측−실제| / Σ|실제|. MAE 단위는 품목의 기록 단위이며, WAPE를 `정확도=100−오차`로 바꾸지 않는다.

## 설치와 자료 보호

연구용 Python 환경에서 한 번 등록한다. 이미 등록된 파일은 덮어쓰지 않는다.

```sh
.venv/bin/python deploy/prepare_records.py --output deploy/.state/records/cheonan-records-v1.json
docker compose -f deploy/compose.yaml build api timesfm web
python3 deploy/prepare.py --checkpoint deploy/.state/model
docker compose -f deploy/compose.yaml up -d --no-build
```

API와 업무 컨테이너에 집계 JSON 하나만 읽기 전용으로 마운트한다. 원자료·환자 개인 행·비밀값을 이미지에 포함하지 않는다. 기본 서버 내보내기는 이 사설 실제 집계 파일도 제외하므로 다른 서버에서 실제 자료 업무를 사용하려면 해당 서버의 사설 자료 등록이 필요하다.

### 그래프 표시 보완 (2026-10-22)

이전 예측의 14일 전체 곡선을 회색 점선으로 가장 위에 그려 이번 예측과 겹치는 구간에서도 확인할 수 있도록 한다. 화면의 MAE·WAPE 약어는 각각 «하루 평균 오차 N단위», «실제 사용량 대비 오차 N%»로 풀어 쓴다. 물품에는 출고량으로 표시하며, 날짜별 절대 차이를 합산한 비율이고 두 수치 모두 작을수록 실제와 가깝다는 설명을 붙인다. 계산 방법과 평가 기간은 유지한다. 최신 사진은 `runs/cheonan/records_screenshots_20261022_02/`에 보존한다.

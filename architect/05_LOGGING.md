## 공통 로거와 보존 정책

### 기록 경로

공통 Python 로거 라이브러리는 형식·민감정보 제거·로그 큐 발행을 담당한다. API·수신·TimesFM·업무·전달 실행기는 같은 계약을 사용한다. 각 프로세스에 라이브러리가 존재하며, 실제 DB 로그 기록은 독립 로거만 수행한다. 애플리케이션 로그의 별도 파일 저장소나 직접 DB 쓰기 우회 경로는 만들지 않는다.

로그는 `event_id`, `occurred_at`, `ingested_at`, `level`, `service`, `code`, `message`, `correlation_id`, 해당되는 `job_id / attempt / input_snapshot_id / proposal_id / order_id`, 허용된 오류 종류를 포함한다. 환자 행·식별자·전체 요청 본문·인증정보·DB 연결 문자열을 기록하지 않는다. DB 로그 테이블은 이벤트 ID 고유 제약으로 재전달을 흡수한다.

### 장애와 유실의 선택

기술 로그는 업무를 무기한 기다리게 하지 않는 best-effort 정책을 택한다. INFO·ERROR 모두 큐·DB 장애나 용량 초과 시 유실될 수 있으며 무손실이라고 표현하지 않는다. 반면 승인·주문·입고·최종 작업 실패는 업무 DB에 원자적으로 보존하므로 기술 로그 유실로 업무 근거가 사라지지 않는다.

| 항목 | 가상 평가 기본값 |
|---|---|
| 생산자 버퍼 | 프로세스별 1,000건 또는 5 MiB 중 먼저 도달한 한도 |
| 발행 방식 | 업무 스레드는 로컬 제한 버퍼에 적재, 별도 발행 루프가 큐로 전송 |
| 개별 발행 대기 | 최대 1초, 실패 로그는 최대 60초까지 버퍼에서 재시도 후 폐기 |
| 버퍼 초과 | DEBUG·INFO를 먼저 폐기하고 남은 초과는 오래된 로그부터 폐기 |
| 본문 크기 | 민감정보 제거 후 최대 16 KiB, 초과 내용은 제한·표시 |
| 로그 큐 | durable classic, 최대 10,000건 또는 64 MiB, TTL 24시간, overflow `drop-head` |
| 로그 소비 | prefetch 200, 최대 200건 또는 1초 간격 배치, DB 연결 상한 2개 |
| DB 오류 | 소비 일시 중단·미확인 메시지 수 제한, 5·10·30초 간격 후퇴 |
| DB 보존 | 수집시각 기준 30일, 하루 1회 제한된 배치로 만료 로그 삭제 |
| 크기 경보 | 로그 관계·인덱스 합계 1 GiB에서 조기 보존 정리·점검, 계속 증가하면 소비 일시 중단 후 관리 조치 |

버퍼와 큐 상한은 먼저 도달한 제한을 적용한다. 큐 크기는 본문 크기 기준으로 실제 디스크 사용량 전체의 상한이 아니다. DB 정리도 즉시 운영체제 디스크 공간을 반환한다고 가정하지 않는다. autovacuum·인덱스·디스크 여유를 함께 관측한다.

로그도 배치 저장 커밋 후 ack하며, 재전달은 `event_id`로 흡수한다. 1 GiB는 경보 기준이며 자동 삭제로 물리 크기가 그 이하로 유지된다는 보장은 아니다. 보존 정리로 줄지 않는 경우 공간 재사용·테이블 정비를 확인하고 로거 상태를 정상으로 표시하지 않는다.

생산자는 폐기 횟수를 메모리 카운터에 보관하고 연결 복구 후 요약 로그를 큐에 보낸다. 프로세스 자체가 종료되면 미전송 로그와 카운터도 유실될 수 있다. 이 카운터를 정확한 손실 원장으로 사용하지 않는다. 잘못된 로그는 유한 횟수 후 폐기하고 원문을 다시 로그로 만들지 않는다.

로거 자신의 저장 실패는 동일 큐로 재귀 발행하지 않는다. 로거는 상태 검사에 장애를 노출하고 DB·브로커의 상태 및 큐 적체로 탐지한다. 비상 로컬 애플리케이션 로그 저장은 초기 정책에 추가하지 않는다. 컨테이너 런타임과 DB·브로커 자체 진단 로그는 애플리케이션 로그 계약과 구분하고 자격정보 노출 없이 순환 보관한다.

큐 분리는 브로커 전체 자원 장애를 격리하지 않는다. 로그와 업무 발행 연결을 분리하고 브로커 경보 시 로그 발행을 먼저 중단해도, 같은 노드의 디스크·메모리 고갈은 전체 작업을 멈출 수 있다. 이 경우 업무는 DB·Outbox에 대기하고 복구 후 재개한다. [RabbitMQ 자원 경보](https://www.rabbitmq.com/docs/alarms), [메시지 TTL](https://www.rabbitmq.com/docs/ttl)

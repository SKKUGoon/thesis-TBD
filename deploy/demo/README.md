# 천안의료원 서버 데모 v0.1

Python 3.11+와 Docker Compose v2가 필요합니다. 웹·Python API 두 컨테이너만 실행하며 TimesFM·PyTorch·체크포인트·PostgreSQL·RabbitMQ는 포함하지 않습니다. 프론트엔드는 로컬에서 빌드한 정적 파일을 포함합니다. 서버에는 Node.js·npm이 필요 없으며 첫 빌드 시 컨테이너 이미지와 고정된 Python 의존성만 내려받습니다.

2026-11-03 현재 구성을 데모 버전으로 확정했습니다. 이 폴더의 Compose는 생성한 이전 묶음 안에서 실행합니다. 공개 저장소에는 시드·DB·접속 토큰·완성 묶음이 없으므로 Git clone만으로 병원 자료 데모를 시작할 수는 없습니다.

## 서버에서 시작

묶음을 서버의 비공개 경로에 압축 해제한 뒤 해당 디렉터리에서 실행합니다.

```sh
python3 prepare.py
docker compose up -d --build
```

기본 접속 주소는 http://127.0.0.1:8090 입니다. 외부 접근을 허용하려면 서버에서 다음처럼 실행합니다. 별도 HTTPS 프록시가 있으면 기본 loopback 바인딩을 유지하십시오.

```sh
BIND_ADDRESS=0.0.0.0 WEB_PORT=8090 docker compose up -d --build
```

접속 화면에서 `private/access-token` 파일을 선택합니다. 이 토큰은 관리자 권한이므로 비공개로 전달합니다. 화면에는 데모 배너가 없으며 업무 설정 안의 `Demo Setting`에서 재생 방식을 조절합니다.

## 설정

`config.json`의 `start_date`는 시드에 포함된 예측 원점 날짜입니다. `forecast_loading_seconds`는 0–600초 정수입니다. 파일 설정은 새 상태 볼륨의 최초 기동에 적용됩니다. 실행 후에는 **업무 설정 → Demo Setting**에서 변경하십시오. 저장하면 새 업무가 열리고 기존 이력은 보존됩니다. 시작 화면은 해당 날짜의 기존 예측을 즉시 보여주며 이후 `주간 자료 전달`부터 설정한 대기 시간을 적용합니다.

예측 날짜를 임의로 오늘로 바꾸지 않습니다. 저장된 원점 밖으로 진행하면 예측 결과가 없다는 오류를 반환합니다. 현재 시드는 2024-01-01–2024-12-16의 월요일 51개, 30품목 × 14일 예측입니다. 각 원점 전날까지의 실제 사용·출고량과 과거 28일 환자 3개 집계만 반환합니다.

실재고·포장 단위·납기는 미등록이며 실제 발주·공급처 처리는 하지 않습니다. 기존 확정 대시보드와 주문 기능의 미등록 표시를 유지합니다. 결과는 저장된 TimesFM 연구 결과를 재생하는 것이며 서버에서 모델을 실행하거나 외부 예측 서버에 연결하지 않습니다.

## 보존·중지·교체

```sh
docker compose stop
docker compose start
```

설정·주차·대기 중인 작업·요청 중복 방지·이력은 `state` 볼륨의 SQLite에 보존됩니다. 중지 중 대기 시간이 지났다면 재시작 후 첫 조회에서 완료됩니다. `docker compose down -v`는 업무 이력을 지우므로 보존 시 사용하지 마십시오. 시드를 교체할 때는 새 묶음과 별도 Compose 프로젝트/볼륨을 사용합니다. API는 기존 볼륨과 다른 시드의 혼합을 거부합니다.

`manifest.json`에 파일별 SHA-256과 예측 수를 기록했습니다. 시드는 집계 데이터와 예측만 포함하며 원자료·개별 환자 행·기존 서버 자격정보·모델은 포함하지 않습니다. 묶음과 시드는 비공개로 보관하십시오.

## 원본 작업 공간에서 다시 만들기

로컬 개발 환경에는 Node.js 22·npm과 pandas/Parquet를 읽을 수 있는 연구용 Python 환경이 필요합니다. 먼저 `npm --prefix frontend ci`로 고정 의존성을 설치하고, 사설 집계 자료와 기존 예측 실행 폴더를 준비합니다. 실행 가능한 이전 묶음은 아래 명령으로 생성합니다. 서버에는 Node.js가 필요하지 않습니다.

```sh
.venv/bin/python deploy/demo/build_bundle.py --output runs/cheonan/portable_demo_새실행번호/bundle
```

출력 디렉터리와 같은 위치에 `.tar.gz`도 생성됩니다. 기존 출력에는 덮어쓰지 않습니다. 추가 모델 실행 없이 기존 평가 예측만 읽습니다.

## 데모 전용 기능과 모델 전환

묶음의 API는 기본적으로 `DEMO_MODE=true`입니다. 상단 **TimesFM / Naive** 버튼을 누르면 모델이 전환되며, 마우스를 올리면 **모델 변경**을 표시합니다. 약품 그래프·검증 오차·14일 합계·테이블과 우측 예측 수량을 함께 갱신합니다. 물품 예측은 기존 값을 유지합니다. 선택은 현재 화면에서만 유지하며 새로 접속하면 TimesFM으로 시작합니다.

Naive는 예측 기준일 직전 7일의 실제 사용량을 다음 14일에 요일별로 반복합니다. 둘째 주에도 예측 이후 실제값을 사용하지 않습니다. 미관측 입력은 미관측으로 유지하며, 완전한 14일 값이 없으면 합계를 계산하지 않습니다. 이전 예측의 MAE·WAPE는 두 모델 모두 실제값과 Naive 입력이 있는 공통 날짜만 평가합니다. 실제 주문량 반복이나 주문 효율성 시뮬레이션이 아닙니다.

데모 기능을 끄려면 묶음 폴더의 `.env`에 다음을 추가한 뒤 `docker compose up -d`로 API를 재생성하고 화면을 새로고침하십시오. 이미지 재빌드는 필요 없습니다.

```dotenv
DEMO_MODE=false
```

OFF 상태에서는 모델 전환 버튼과 Demo Setting을 숨기고 Naive 조회·데모 설정 API를 차단합니다. 기존 TimesFM 결과와 업무 상태는 보존합니다. 이 설정만으로 실제 모델·병원 운영 시스템으로 전환되는 것은 아닙니다. 다시 켜려면 `DEMO_MODE=true`로 변경합니다. 잘못된 값은 OFF로 처리합니다.
